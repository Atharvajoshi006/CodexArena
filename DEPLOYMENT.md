# Deployment Guide — Supabase + Render + Vercel

## Architecture

```
User Browser
    │
    ▼
Vercel  (free frontend proxy)
    │  rewrites all requests to →
    ▼
Render  (free Django backend)
    │  reads/writes to →
    ▼
Supabase  (free PostgreSQL database)
```

---

## Step 1 — Create a Supabase Database (free)

1. Go to https://supabase.com and sign up / log in
2. Click **New project** — fill in a name (e.g. `codexarena`) and a strong DB password
3. Wait ~2 minutes for the project to provision
4. Go to **Project Settings → Database → Connection string**
5. Select the **Transaction pooler** tab (important — port **6543**)
6. Copy the connection string — it looks like:
   ```
   postgresql://postgres.[ref]:[YOUR-PASSWORD]@aws-0-[region].pooler.supabase.com:6543/postgres
   ```
7. Append `?sslmode=require` to the end:
   ```
   postgresql://postgres.[ref]:[YOUR-PASSWORD]@aws-0-[region].pooler.supabase.com:6543/postgres?sslmode=require
   ```
8. Save this — you'll paste it into Render as `DATABASE_URL`

---

## Step 2 — Deploy on Render (free backend)

1. Go to https://render.com and sign up / log in with GitHub
2. Click **New → Web Service**
3. Connect your GitHub repo (`Atharvajoshi006/CodexArena`)
4. Set the following:
   - **Name**: `codexarena-backend`
   - **Environment**: `Python 3`
   - **Build Command**: 
     ```
     pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate
     ```
   - **Start Command**: 
     ```
     gunicorn codexarena.wsgi:application
     ```
   - **Plan**: Free
5. Scroll down to **Environment Variables** and add:

   | Key | Value |
   |-----|-------|
   | `DATABASE_URL` | Your Supabase connection string from Step 1 |
   | `DEBUG` | `false` |
   | `ALLOWED_HOSTS` | `codexarena-backend.onrender.com,localhost` |
   | `CSRF_TRUSTED_ORIGINS` | `https://codexarena-backend.onrender.com` |
   | `BACKEND_PUBLIC_URL` | `https://codexarena-backend.onrender.com` |
   | `GOOGLE_OAUTH_CLIENT_ID` | Your Google OAuth client ID |
   | `GOOGLE_OAUTH_CLIENT_SECRET` | Your Google OAuth client secret |
   | `GOOGLE_OAUTH_REDIRECT_URI` | `https://codexarena-backend.onrender.com/google/callback/` |
   | `SESSION_COOKIE_SAMESITE` | `None` |
   | `CSRF_COOKIE_SAMESITE` | `None` |

   > `SECRET_KEY` is auto-generated by Render from `render.yaml` — no need to set it manually.

6. Click **Create Web Service** and wait for the first deploy to finish
7. Note your Render URL: `https://codexarena-backend.onrender.com`

---

## Step 3 — Deploy on Vercel (free frontend proxy)

1. Go to https://vercel.com and sign up / log in with GitHub
2. Click **Add New → Project** and import `Atharvajoshi006/CodexArena`
3. **Framework Preset**: select `Other`
4. Leave build settings blank (no build needed — `vercel.json` handles everything)
5. Click **Deploy**
6. Note your Vercel URL: e.g. `https://codexarena.vercel.app`

---

## Step 4 — Update Render with your Vercel URL

Go back to Render → your service → **Environment** and update/add:

| Key | Value |
|-----|-------|
| `FRONTEND_URL` | `https://codexarena.vercel.app` |
| `CSRF_TRUSTED_ORIGINS` | `https://codexarena-backend.onrender.com,https://codexarena.vercel.app` |
| `ALLOWED_HOSTS` | `codexarena-backend.onrender.com,codexarena.vercel.app,localhost` |

Click **Save Changes** — Render will auto-redeploy.

---

## Step 5 — Update Google OAuth for Production

1. Go to https://console.cloud.google.com/apis/credentials
2. Open your OAuth 2.0 Client ID
3. Add to **Authorized redirect URIs**:
   ```
   https://codexarena-backend.onrender.com/google/callback/
   ```
4. Add to **Authorized JavaScript origins**:
   ```
   https://codexarena-backend.onrender.com
   https://codexarena.vercel.app
   ```
5. Save

---

## Notes

- **Render free tier** spins down after 15 minutes of inactivity. The first request after idle takes ~30 seconds to wake up.
- **Supabase free tier** gives 500MB storage and pauses after 1 week of inactivity — log in to Supabase to unpause.
- **Vercel** is fully free for this use case (just a reverse proxy).
- Local development still uses SQLite when `DATABASE_URL` is not set in `.env`.
